# 训练代码改动说明

本文档记录本次为修正实验可信度而做的代码改动，以及后续重跑实验时需要注意的事项。

## 1. 改动目标

本次改动主要解决两个问题：

1. `best valid PPL` 与策略控制评估可能不是同一个 checkpoint 得到的。
2. DeSTRS 的策略分类辅助监督默认没有稳定作用在 `delta_prefix` 上，和“让 Prefix 承载策略信号”的设计目标不完全一致。

评估样本数量暂不直接修改默认配置，后续由实验运行时统一调大。

## 2. Checkpoint 与 swap samples 对齐

旧逻辑中，训练过程会在 valid loss 最好时保存 checkpoint，但训练结束后又无条件保存 final checkpoint，并用 final 内存模型生成 `swap_samples_valid.jsonl`。

这样会导致：

- `metrics.json` 中的 best valid/test PPL 来自 best epoch；
- `strategy_eval_llm.json` 评估的生成样例可能来自 final epoch；
- 下游 B7/B8/B9 warm-start 也可能继承 final checkpoint，而不是 best checkpoint。

现在逻辑改为：

- 当 `save_best_only=true` 时，`output/other/{dataset_tag}/{experiment_name}` 保留 best checkpoint；
- 训练过程中记录 best epoch 的可训练参数快照；
- 训练结束后恢复 best epoch 参数，再生成 `swap_samples_valid.jsonl`；
- `metrics.json` 额外记录：
  - `best_epoch`
  - `save_best_only`
  - `swap_samples_checkpoint`

因此默认设置下，PPL 表格和 LLM 策略评估会对应同一个 best checkpoint。

## 3. 分类辅助监督目标

新增配置项：

```json
"cls_target": "h_real"
```

可选值：

- `h_real`：使用 both-on 前向中的真实 token hidden states，兼容旧行为；
- `delta_prefix`：使用 prefix-only hidden state 与 base-only hidden state 的差值。

B6/B7 配置已改为：

```json
"cls_target": "delta_prefix"
```

这样分类损失会更稳定地约束 Prefix 引入的策略增量，而不是主要约束 both-on 的整体隐藏表示。

## 4. 需要重跑的实验

本次代码改动会影响所有需要训练并生成 swap samples 的实验，尤其是：

- B5/B6：之前 best epoch 与策略评估 checkpoint 可能不一致；
- B7/B8/B9：依赖 B2/B3 的 checkpoint，应该在 B2/B3 用新逻辑重跑后再重跑；
- B6/B7：`cls_target="delta_prefix"` 改变了训练目标。

建议重跑命令：

```bash
FORCE_RETRAIN=1 FORCE_EVAL=1 DATASET_TAG=casino_augmented DATASET_DIR=./augmented_data ./run_all.sh
```

如果只想先验证主消融，可以先重跑 B2-B6，再重跑 B7-B9。

## 5. 评估样本数量

当前默认仍是：

```json
"demo_num_examples": 5
```

即 5 个 valid 样本乘 9 个策略，共 45 条生成。这个规模只能观察趋势，不适合支撑稳定论文结论。

后续建议统一调大为：

- `demo_num_examples=30`，对应 270 条生成；
- 或 `demo_num_examples=50`，对应 450 条生成。

运行 LLM 评估时也要同步放大上限，例如：

```bash
EVAL_MAX_SAMPLES=270 FORCE_RETRAIN=1 FORCE_EVAL=1 DATASET_TAG=casino_augmented DATASET_DIR=./augmented_data ./run_all.sh
```

如果手动改配置文件中的 `demo_num_examples`，需要保证 `EVAL_MAX_SAMPLES >= demo_num_examples * 9`。

## 6. 结果解读注意事项

重跑后再更新论文表格和 `实验现状与后续计划.md`。旧结果中 B8/B9 与当前新定义不一致，不能直接混用。

新的实验表应注明：

- PPL 与策略评估均来自 best checkpoint；
- B6/B7 的分类辅助监督目标为 `delta_prefix`；
- LLM 策略评估样本数量为实际生成条数。

## 7. 补足样本后的重跑步骤

如果后续已经补足增强数据样本，并希望重新得到一整套干净结果，建议按下面步骤执行。

### 7.1 修改生成评估样本数量

在各个实验配置中把：

```json
"demo_num_examples": 5
```

改成计划使用的样本数。例如：

```json
"demo_num_examples": 30
```

这会生成 30 个 valid 上下文乘 9 个策略，共 270 条策略控制样例。

如果改成：

```json
"demo_num_examples": 50
```

则会生成 450 条策略控制样例。

### 7.2 删除旧输出目录

为了避免脚本跳过已有结果，重跑前删除旧的分析结果和模型权重：

```bash
rm -rf output/need/casino_augmented output/other/casino_augmented
```

两个目录都要删除：

- `output/need/casino_augmented` 保存 `metrics.json`、`swap_samples_valid.jsonl`、`strategy_eval_llm.json`；
- `output/other/casino_augmented` 保存 checkpoint，B7/B8/B9 会依赖 B2/B3 的权重。

只删其中一个可能导致脚本跳过训练，或让依赖实验加载旧 checkpoint。

### 7.3 重新运行全部实验

如果 `demo_num_examples=30`，运行：

```bash
EVAL_MAX_SAMPLES=270 \
DATASET_TAG=casino_augmented DATASET_DIR=./augmented_data \
./run_all.sh
```

如果 `demo_num_examples=50`，运行：

```bash
EVAL_MAX_SAMPLES=450 \
DATASET_TAG=casino_augmented DATASET_DIR=./augmented_data \
./run_all.sh
```

规则是：

```text
EVAL_MAX_SAMPLES >= demo_num_examples * 9
```

如果已经删除旧输出目录，就不一定需要加 `FORCE_RETRAIN=1 FORCE_EVAL=1`。脚本会因为结果不存在而重新训练和评估。

如果不删除旧输出目录，则必须使用：

```bash
FORCE_RETRAIN=1 FORCE_EVAL=1
```

否则 `run_all.sh` 会发现已有 `metrics.json` 或 `strategy_eval_llm.json`，然后跳过对应步骤。
