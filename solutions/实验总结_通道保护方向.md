# Solutions 实验总结：通道保护方向的负结果

本文档总结 `solutions/` 下这一轮补充实验的代码审计、有效结果和结论。核心问题是：

> Prefix + LoRA 联合训练后，LoRA 改善 PPL 但显著损害策略可控性。我们尝试通过“适应 LoRA 空间”或“保护 Prefix 通道”来恢复控制，但结果显示这条方向基本不成立。

## 一、是否可能是代码没写对？

结论：当前能够确认的有效实验里，主要失败结果不太像代码写错导致。

### S1 Reverse Curriculum

S1 的设计是：

1. Stage 1：只训练 LoRA，不启用 Prefix。
2. Stage 2：加载 Stage 1 LoRA，冻结 LoRA，只训练 Prefix。

已检查 `run_config.json`，关键配置正确：

```json
{
  "warm_start_dir": "solutions/output/other/casino_augmented_new_fix_seed42/s1_clean_stage1_lora_only",
  "warm_start_prefix": false,
  "warm_start_lora": true,
  "inject_strategy_text": false,
  "enable_lora": true,
  "train_prefix": true,
  "train_lora": false
}
```

代码路径也吻合设计：

- `run_s1_reverse.py` 在 Stage 2 中显式设置 `enable_lora=true`、`train_prefix=true`、`train_lora=false`。
- `src/modeling.py::attach_lora` 会从 `warm_start_dir/lora_adapter` 加载 LoRA。
- `src/modeling.py::freeze_for_adapter_mode` 会冻结 LoRA，仅开放 Prefix。
- S1 Stage 2 的 PPL 仍接近 LoRA 模型区间，而不是退回 Prefix-only 的高 PPL，这说明 frozen LoRA 确实参与了前向。
- `prefix_norm_before=17.17`，`prefix_norm_after=43.43`，说明 Prefix 确实被训练。

因此，S1 更像有效负结果，而不是明显配置或训练路径错误。

### S2 Parameter-Level Orthogonality

S2 最初确实有实现问题：4-bit base projection weight 被错误处理，导致 QK/VO loss 全部 skip，`train_param_orth_qk=0`。这一版结果不能作为方法结论。

修复后重新跑 S2_qk v3，诊断指标为：

```text
param_orth_calls > 0
param_orth_avg_n_qk = 36.0
param_orth_avg_skipped_qk = 0.0
skip_shape = 0.0
skip_gqa = 0.0
lora_layers = 36.0
base_layers = 36.0
train_param_orth_qk > 0
```

这说明修复版 S2_qk 已经真实接入 36 层 QK 参数正交约束，没有再被 shape/GQA 逻辑跳过。S2_qk v3 的低准确率可以视为有效结果。

### S4 Contrastive Prefix Decoding

S4 旧结果无效。旧代码在 `temperature=0.0` 时会执行 logits 除以 0，导致生成大量 `!!!!`。该 bug 已修复，但修复后尚未重新完整评估，因此本文档不把 S4 当作有效负结果。

## 二、关键结果

### 主对比

| 实验 | 是否有效 | 策略准确率 | 备注 |
|---|---:|---:|---|
| B3 Prefix-only | 是 | 55.93% | 策略控制最好，但 PPL 高 |
| B4 Prefix+LoRA | 是 | 37.17% | PPL 好，但控制下降 |
| B9 Prefix-then-LoRA | 是 | 38.89% | Prefix 冻住后 LoRA 仍破坏控制 |
| S1 Reverse Curriculum | 是 | 15.93% | 反转训练顺序失败 |
| S2_qk old | 否 | 35.19% | 参数正交 loss 没有真实接入 |
| S2_qk v3 | 是 | 27.41% | QK 正交真实接入后更差 |
| Gold judge calibration | 是 | 54.35% | 真实回复上的 judge 上限较低 |

### S1 结果

S1 Stage 2 补到 270 个 swap 样本后：

```text
strategy accuracy = 15.93%
```

预测分布严重塌缩到少数策略：

```text
self-need: 119 / 270
small-talk: 98 / 270
```

这说明“先铺路，再学 Prefix”没有恢复 9 类策略可控性。Prefix 在固定 LoRA 空间中重新训练，仍然会被标准 LM loss 推向高频、低风险的通用谈判回复。

### S2_qk v3 结果

S2_qk v3 的参数正交约束真实生效后：



这说明语言流畅性没有崩，但策略控制进一步变差。

这说明自动策略准确率有明显评估噪声，尤其 `other-need`、`promote-coordination`、`vouch-fair`、`showing-empathy` 等策略本身边界模糊。

但这不能完全解释 Prefix+LoRA 的 trade-off，因为 B3 Prefix-only 仍能达到 55.93%，几乎接近 gold judge 校准水平；而 B4、B9、S1、S2_qk v3 都明显低于 B3。

## 三、为什么这个方向不对？

这一轮 `solutions/` 实验原本假设：

> LoRA 修改了 attention 的 Q/K/V/O 投影，因此 Prefix 信号在穿过 LoRA 修改后的 attention 空间时被扭曲。只要让 Prefix 适应该空间，或在参数层面保护 Prefix 通道，就能恢复策略控制。

实验不支持这个假设。

S1 说明：

> 即使 Prefix 从一开始就在 LoRA 修改后的空间中训练，也不能学出稳定的策略可切换行为。

S2_qk v3 说明：

> 即使 QK 参数正交真实接入，并约束 LoRA Query 更新不要读取 Prefix key 子空间，也不能恢复输出端策略区分度，反而会进一步降低策略准确率。

更准确的问题表述应该是：

> 标准 LM loss 对策略身份不敏感。LoRA 提升流畅度后，模型更倾向于生成高概率、通用、低风险的谈判回复；Prefix 的内部差异即使存在，也没有足够训练压力稳定反映到最终输出行为。

因此，问题不是单纯的“Prefix 通道被 LoRA 挡住了”，而是：

> 参数空间或表示空间的分离，不保证功能层面的可控生成。

这个结论可以作为论文中的重要负结果：

> Parameter-space or representation-space interventions do not guarantee functional controllability under a strategy-insensitive LM objective.

## 四、哪些结果可以写进论文？

可以写：

1. S1 作为有效负结果：反转课程学习不能恢复控制。
2. S2_qk v3 作为有效负结果：参数交互层面的 QK 正交不能恢复控制，甚至更差。
3. Gold judge calibration：自动策略评估存在噪声，模型结果需要结合校准和类别混淆解释。
4. 机制结论：LM loss 的策略不敏感性比 attention 通道扭曲更根本。

暂时不要写：

1. S2_vo / S2_full 的最终结论，因为它们旧结果是在参数正交未真实接入时跑出来的。
2. S4 CPD 的结论，因为旧结果有 temperature=0 除零 bug。
3. S3 attention analysis 的结论，因为当前没有有效输出。

## 五、下一步应该换什么方向？

不建议继续主要围绕“保护 Prefix 通道”做方法。下一步应转向输出级功能约束：

```text
直接让最终回复体现目标策略，而不是只约束内部参数或隐藏表示。
```

建议新方向：

### Strategy-Contrastive Preference Optimization

基本思路：

1. 固定一个流畅模型，例如 B4 或 B9。
2. 对同一个 context，用 9 个 Prefix 分别生成回复。
3. 用 LLM judge 或人工规则筛出：
   - chosen：被判为目标策略的回复；
   - rejected：被判为错误策略的回复。
4. 冻结 LoRA，只微调 Prefix。
5. 使用 DPO / pairwise ranking / hinge preference loss，让目标策略 Prefix 下 chosen 分数高于 rejected。

这样训练目标直接作用于输出行为，而不是假设 token-level LM loss 会自然保留策略差异。

一句话：

> 旧方向是在修“信号通道”；新方向应该直接优化“输出行为”。
