  改动方案讨论
  
  基于之前的诊断，问题根源清晰：L_orth 占总 loss 的 0.07%，L_cls 占 0.68%，两个策略信号被生成损失完全淹没。同时分类器的输入选择存在设计矛盾。

  改动一：分类器输入从 h_both 改为 delta_prefix（代码改动）

  现状（losses.py:230）：
  cls_loss, cls_logits = classification_loss(hybrid, h_both, labels, strategy_ids)
  分类器从 prefix+LoRA 混合表示 中学习策略信号。

  问题：
  - orth 的目标是把 prefix 和 LoRA 推远（正交化）
  - cls 的目标是让 classifier 能识别策略
  - 如果 cls 读的是 h_both（两者混合），那它需要 prefix 和 LoRA "合作"才能被分类器识别
  - 这跟 orth 的方向是矛盾的，也是 B6 正交性反而比 B5 差的原因

  修改：
  cls_loss, cls_logits = classification_loss(hybrid, delta_prefix, labels, strategy_ids)
  让分类器只从 prefix 的增量表示（h_prefix - h_base）中识别策略。这样 orth 和 cls 的方向就一致了——orth 推远 prefix 和 LoRA，cls 让 prefix 单独学会承载策略信号。

  改动二：orth_every_n_steps 从 20 改为 1（config 改动）

  现状：每 20 步才注入一次正交信号，3820 步中只有 ~188 次。

  改为 1：每一步都计算正交损失。代价是每一步做 4 次前向传播（base / prefix-only / lora-only / both），训练速度降低约 4 倍。但对于 1900 条样本、5 epoch 的数据规模来说，这可以接受。

  非 orth 路径（losses.py:108-150）会自然变成死代码，可以保留作为 fallback 不做改动。

  改动三：λ_orth 和 λ_cls 大幅提高（config 改动）

  需要让 orth 和 cls 的贡献达到总 loss 的 5-15%：

  ┌────────┬──────┬──────────┬───────────┐
  │  参数  │ 当前 │ 目标占比 │  建议值   │
  ├────────┼──────┼──────────┼───────────┤
  │ λ_orth │ 0.05 │ 2-10%    │ 0.5 → 2.0 │
  ├────────┼──────┼──────────┼───────────┤
  │ λ_cls  │ 0.2  │ 5-15%    │ 1.0 → 3.0 │
  └────────┴──────┴──────────┴───────────┘

  具体数值需要通过实验搜索。建议第一轮跑 3 个组合：

  组合 A: λ_orth=1.0, λ_cls=2.0  （温和）
  组合 B: λ_orth=2.0, λ_cls=3.0  （中等）
  组合 C: λ_orth=5.0, λ_cls=5.0  （激进）

  改动四：训练轮数从 2 改为 5（config 改动）

  Prefix bank 有 737K 参数，2 个 epoch 只有 3820 步，对于一个从头学习的 embedding 来说可能不够。

  不需要改的代码

  - losses.py 中的正交损失计算逻辑：local_global_orth_loss 的设计是合理的（local cosine 惩罚 + global Frobenius 惩罚），不需要改动
  - modeling.py：HybridStrategyModel 的架构暂时不需要改动
  - 数据集/数据加载：不需要改动
  - 非 orth 路径：保留原样，当 orth_every_n_steps=1 时自然不会被用到
